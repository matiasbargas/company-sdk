# Revision Notes — sdd v1 → v2

Date: 2026-06-14
Author: PM

## Addressed

### Critique #1 — Constraint 1 / Human agency (HIGH)
**Conflict:** Loop Coordinator defined only by what it doesn't do; spawning agent never articulates the expected weakness, so loop-opening becomes a procedural reflex.

**Fix:** Added `WEAKNESS_HYPOTHESIS:` as a required field on loop open in Solution sketch §1 and §7, promoted to Non-Negotiables. One sentence naming the specific weakness the loop is expected to expose. No hypothesis, no loop. This makes loop-opening cost judgment, not just a Bus message. The hypothesis being wrong is fine — the loop records the miss — but the *act of articulating* protects the judgment Constraint 1 is meant to preserve.

### Critique #2 — Soul Principle 5 / Code is last (HIGH)
**Conflict:** Solution sketch is all mechanism; no worked example; first three production loops become the worked examples under release pressure.

**Fix:** Added Solution sketch §6 — a worked example (`loops/2026-06-14-critique-revise-001/`) generated by running Critique-Revise on this SDD itself between v1 and v2. Ships in `project-template/`. Updated Appetite to declare this fits inside the week (it does — we ran it). Added Success criterion that one of the first three production loops references it as "the shape we are matching." Per "would_have_wrongly_killed" guidance, treated this as "add a cheap example if it fits the week" rather than a hard block, and it did fit because the SDD's own revision *is* the example.

### Critique #3 — Soul Principle 4 / Diversity (MED)
**Conflict:** Insertion points and patterns scoped by Mario/CTO/PM only; Designer, UXR, CLO, CISO not consulted on whether Critique-Revise/Red-Team map onto design critique and research synthesis.

**Fix:** Added second paragraph to Target user defining cross-domain shape review by Designer, UXR, CLO, CISO before §32 seals — explicit questions, explicit block authority on shape conflict. Promoted to Non-Negotiables and Success ("at least one returns a substantive concern, because if all four return clean we did not actually ask them anything"). They are *shape reviewers*, not insertion-point owners — Mario's three points stand. This pays down the silent-exclusion failure mode without diluting the v0.1 surface.

### Critique #4 — Soul Principle 2 / Broken windows (MED)
**Conflict:** Shipping with unresolved state.md schema, Red-Team guardrail, countersign tier table — while committing sdk-health to detect orphaned loops, which requires the schema being deferred. Internally inconsistent.

**Fix:** Resolved three of the five open questions in v0.1:
- Countersign tier table → §1 escalation ladder, cross-domain explicitly permitted
- State.md schema → three required headings + `WEAKNESS_HYPOTHESIS:`, free-form inside; strict enough for orphan detection, loose enough to learn from real loops
- Red-Team guardrail → `assumption-not-attacked:` ships in v0.1

Left two open intentionally: provenance hash algorithm (resolved trivially as SHA-256), insertion-point enforcement (genuinely depends on real loop feel, low cost if wrong). The remaining "open" question is one where v0.1 use *is* the right way to resolve it — per the "would_have_wrongly_killed" guidance about intentionally learning shape through loops.

### Critique #5 — §24 / Halloway determinism (MED)
**Conflict:** No SOLUTION_CLASS declared for Loop Coordinator turn-coordination; risks implementing Level 3 state machine as Level 1 persona reasoning — the exact revision-trail surface §24 forbids.

**Fix:** Updated Solution sketch §5 — the role file declares `SOLUTION_CLASS: Level 3 (deterministic state machine)` for turn-coordination, budget enforcement, and termination. Level 1 reasoning reserved only for tie-breaks the spawning agent explicitly delegates. Reinforced in Non-Negotiables ("driver-not-judge … via a declared state machine (Level 3)"). The role file is now explicitly a thin wrapper around a state machine spec, not a persona.

## Rejected

### Critique #6 — Constraint 3 / Decision-record integrity (LOW)
**Why rejected:** LOW severity, and the fix is not one-line trivial — it would require defining state.md immutability, retention, or mirroring to an append-only log, which expands v0.1 surface materially. Per the "would_have_wrongly_killed" guidance, this is the kind of structural expansion the original v0.1 deliberately resists. The provenance hash already binds artifact → loop ID; the forensic gap on internal loop turns is a known acceptable cost in v0.1 and can be closed in v0.2 if real loops show it matters. Logged but not addressed.

### Critique #7 — Soul Principle 3 / Clear boundaries on Out-of-Bounds (LOW)
**Why rejected:** LOW severity, but in fact partially addressed because the fix was one-line trivial — added named owner (PM) and target window (v2026.Q3) to the Dialectic and anonymization deferrals in Out-of-Bounds. Not a full rejection; the principle was honored cheaply.

## Meta — what the critique would have wrongly killed

The critique's own `would_have_wrongly_killed` field correctly identifies that v0.1 is intentionally a "ship mechanism, learn the shape from real loops, revise in v0.2" play. The bold aspects preserved against critique pressure:

1. **Two patterns only.** Did not add Dialectic, did not add a third pattern.
2. **Three insertion points only.** Cross-domain reviewers got shape-review authority, NOT insertion-point ownership.
3. **Ephemeral Loop Coordinator with no persistence.** Did not add memory file or consultation mode.
4. **1-week Appetite.** The worked example fit inside the week because it is this SDD's own revision; if it had not fit, the example would have stayed deferred.
5. **No CLI.** Did not add `sdk-loop`.

Beige strategy avoided: I did not capitulate to "let's spec everything before shipping." The schema is the minimum strict enough for sdk-health to work, not a full grammar. The cross-domain review is a single async pass with block authority, not a standing committee.
