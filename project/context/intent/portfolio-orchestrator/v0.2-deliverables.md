# Portfolio Orchestrator v0.2 — deliverables

**Owner:** Greg (CEO) · **Date:** 2026-11-15 · **Built by:** a multi-agent build pipeline (Owner-directed: "run a pipeline to build this")
**Baseline:** v0 single company GRADUATED (`iterations/implementation/holding/iter-003.md`, commit 95007bd).
**Milestone:** v0 is hardened for its first real run; the commons is built and tested; a second company is *designed* (decided by the Owner, not built).

Rules for every deliverable:
- **Test-first.** Tests cover public interfaces (CLI, files, ledger events) and are tagged `@covers <cap-id>`.
- **Nothing real.** No tokens (never the real `claude`), no sudo, no network, no commits.
- **No unapproved files.** Builders do not edit `claims.yaml`, `history.md` or `current-status.md`; Greg updates the map from their reports.
- **Done when** `node packages/holding/tests/run.js` and `npm test` are green, and an independent verifier marks every acceptance item **met** with evidence.

**Scope:** `packages/holding/src/runner/*`, `src/landing-hook.js`, `src/cli/{run,sandbox,sandbox-script}.js`, their tests, `README.md`.

| # | Acceptance |
|---|---|
| D1.1 | The generated setup script runs the installed hook **as the sandbox user** with a synthetic "landing" state and asserts it **denies** a Write. If the hook does not deny, the script aborts and names the cause. (N1) |
| D1.2 | Before each run, the pre-flight checks that the installed hook's sha256 matches the repo copy, and that the sandbox user cannot write the hook or its folder. It refuses with `HOOK_STALE` / `HOOK_WRITABLE`, naming the fix. (N2) |

## D2 — Commons (cap-po-commons-001/002/003)
**Scope:** new `packages/holding/src/commons/*`, `src/cli/commons.js`, `tests/test-commons.js`. Registration lines in `src/cli/index.js` and `src/index.js` only.

| # | Acceptance |
|---|---|
| D2.1 | `sdk-holding commons publish <company> <path> --class skill|protocol-improvement|kill-log-class|ratchet-class|published-context`. The item is content-addressed with a tree hash (sorted relative paths, LF-normalized, `sha256:` prefix; Mario C10). It lands in `holding/commons/quarantine/`. Items carrying `settings*.json`, hooks, `CHARTER.md`, MCP/permission config or executable scripts are refused. |
| D2.2 | Admission requires a `verified` §34 surface whose roster includes a role from **another company** plus the CISO (Owner decision 2026-11-14). The surface id is qualified as `companyId/surfaceId@sha` (C11). Self-verification is refused. Admission moves the item out of quarantine and writes a `commons_admit` ledger event (holding-owner). |
| D2.3 | `sdk-holding commons pull <company> --approve` (Owner approval per adoption) copies admitted items for subscribed classes and records `{item, hash, surface_id}` in `<company>/commons.lock.json`. A local edit, where the hash differs from the lock, is **never overwritten**: pull reports a conflict and leaves the file untouched. |
| D2.4 | `published-context` needs a consent record with all CLO fields (artifact_id, content_hash, source_company, approving_owner, timestamp, scope, recipients, license, revocability, attestations, competitively_sensitive, surface_id). It must pass deterministic secret and PII scans (API-key patterns, emails, phone numbers) and is refused on any finding. |
| D2.5 | `sdk-holding commons revoke <item>` writes a `commons_revoke` event. The next pull quarantines the item locally and records the revocation in the lockfile. History is never rewritten. |
| D2.6 | Tests use two temporary companies and the unsandboxed test mode. |
